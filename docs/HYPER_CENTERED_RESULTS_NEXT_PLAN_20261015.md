## 3. 修复了什么，为什么仍需改模型

### 3.1 全局集中确实缓解，但不是兴趣学习成功的证据

| seed | B 视觉物品四超边占用 | centered 占用 | B 视觉用户 dropout 全零 | centered 全零 |
|---|---|---|---:|---:|
| 999 | 0 / 6754 / 0 / 296 | 1654 / 2333 / 1593 / 1470 | 49.959% | 7.228% |
| 2026 | 2900 / 0 / 0 / 4150 | 2077 / 1432 / 1408 / 2133 | 46.741% | 7.299% |
| 2027 | 1 / 0 / 0 / 7049 | 941 / 1415 / 2638 / 2056 | 49.944% | 7.346% |

视觉物品全零比例也从 B 的 40.53%–49.98% 降为约 6.29%。数值修复确实发生，不能说实现无效。但完整训练后，centered 的视觉物品最大分配概率均值仍为 .9445–.9467，用户为 .9710–.9728；视觉投影范数增至18.37–18.70。三轮检查的高熵状态并没有持续到收敛。

它从“很多节点挤到同一超边”变成了“很多节点分别接近选中四条超边之一”。占用更均衡不代表分组更符合用户偏好。

### 3.2 原有 HCL 被激活，不能只看损失标量

固定 TRAIN 批次、每个检查点三次随机梯度探测：

| 共享物品 ID 上的诊断 | B | centered |
|---|---:|---:|
| 加权 HCL 梯度 / BPR 梯度范数 | 0.0035–0.0095 | 0.471–1.241 |
| centered 中两种梯度的余弦 | — | -0.0123 至 +0.0091 |

加权 HCL 损失仍约 .96–.97，实际影响却由很弱变成与排序梯度同量级。centered 的两个梯度大致正交，不能称为强烈相反；也不能据此证明长期优化一定有害。可检验的假设是：原先近乎失活的对比任务恢复后，未必把新增表达能力用于排序。

因此下一步用有/无原 HCL 的结构消融验证因果，不搜索一串 HCL 权重，也不直接加入梯度手术。

### 3.3 四原型结构与实例级目标存在潜在不匹配

当前 `HGNNLayer` 每模态形成四个超边向量，再让用户和物品做线性混合。给定一次前向，该超图分支的输出矩阵秩至多为四；这不等于整个模型秩为四，因为 CGE/MGE 等分支仍存在。

与此同时，HCL 在这些粗粒度超图表示上进行全体用户或物品的实例区分。这是表达能力与训练目标可能不匹配的代码证据，尚未证明为退化的唯一原因。简单增加超边数量只是容量调整，不能替代结构设计。

centered 视觉物品的训练随机分配与推理分配 L1 差约 .454–.483，128次 Monte Carlo 的 split-half L1 约 .140–.142；视觉训练 argmax 约27%–29%发生变化。此处差异已明显大于该采样误差指标，但不把有限次模拟当精确期望，也不把全部随机增强自动判定为坏。

## 4. 2026 文献提供哪些依据

以下是机制参考，不是与本项目同协议复现的 SOTA 排名。论文指标涉及不同特征、数据切分和 TEST/VALID，不能与本轮 VALID .1013 直接比大小。

1. **MHRec，Expert Systems with Applications 2026**：[出版页](https://www.sciencedirect.com/science/article/pii/S0957417426012248)、[模型内构边实现](https://github.com/Ricardo-Ping/ChaoRec/blob/master/Model/MHRec.py#L561)、[独立预生成脚本](https://github.com/Ricardo-Ping/ChaoRec/blob/master/gen_hypergraph_u_i.py)。作者从训练交互及模态近邻形成局部群组超边，再学习结构。值得借鉴的是把超边锚定到实际群组；不移植其扩散生成和整套双通道网络。本项目拟用已有 TRAIN 共现群组，属于自己的受限改造，不是 MHRec 复现。其两条构边路径的随机截断/补位不完全一致，不能原样复制；本项目应使用唯一成员集合、变长邻居、数据指纹缓存，孤立节点不以物品/用户0填充。
2. **OrthoRec，ACM MM 2026 已录用**：[全文](https://arxiv.org/html/2609.02152v1)、[作者机构录用信息](https://scholars.cityu.edu.hk/en/publications/beyond-modality-harmony-orthogonal-purification-and-topology-guid/)。它针对模态信息与协同偏好的冲突，使用协同信息筛选语义并限制不可靠对齐。本项目只借鉴“贡献应由推荐任务决定”的原则，不移植正交净化、MoE、safe-SSL 全套。截止10月15日，11月会议尚未举行。
3. **DHMRec，AAAI 2026**：[官方论文页](https://ojs.aaai.org/index.php/AAAI/article/view/38661)。题名中的 H 是 Hierarchical Fusion，不能把它误作新的超图构造论文。其协同引导模态处理可作辅助依据，但不为我们的稀疏超边公式直接背书。
4. **AnchorRec，2026年3月预印本**：[全文](https://arxiv.org/html/2603.12726v1)。它把对齐放到独立投影空间以保留原模态结构；这里仅作为重审直接对齐目标的旁证，未核验为顶会录用，不把“competitive”改写成无条件SOTA。本轮不再添加一套投影对齐网络。

## 5. 推荐主线：行为群组定义超边，模态与任务表示决定成员贡献

停止把 centered 继续作为涨点主线。下一版在 LGMRecOpt 内替换原 GHE 的超边构造与传播，保留可复现的 B 路径。仍是 LGMRec 的透明优化扩展，不另起独立模型身份。

### 核心结构

1. **稀疏群组超边**：以物品 j 为锚，用现有 TRAIN count 共现 TopK 建立 `e_j={j}∪N_train(j)`。第一版沿用 K=10、最小共现=2；没有邻居的物品保留单节点超边。集合仅由 TRAIN 决定，不能用 VALID/TEST 补边。
2. **超边内部选择成员贡献**：复用现有模态投影和协同表示，在每条超边内计算内容相关性与协同相关性，得到成员权重。使用归一化方向计算相关性，避免单纯依靠放大投影范数提高权重。
3. **显式两阶段传播**：物品→超边→物品，用户通过 TRAIN 历史聚合得到超图表示。支持关系保持稀疏；基础传播采用训练/推理相同的确定性规则，第一版不继续对超边关联做 Gumbel 抽样。其余局部编码、评分和 B 残差先保持，便于判断新 GHE 的贡献。

一个待实现、待验证的最小参数化示例（不是已完成算法）：

```text
f_i^m = normalize(existing_modal_projection_m(x_i^m))
q_j^m = normalize(mean_{i in e_j} f_i^m)
a_ij^m = softmax_{i in e_j}(cos(f_i^m, q_j^m) + cos(c_i, c_j))
z_j^m = sum_{i in e_j} a_ij^m * c_i
g_i^m = weighted_mean_{j: i in e_j}(z_j^m; a_ij^m)
```

其中 c 是只由 TRAIN 训练的协同表示。两模态在同一行为支持集合上可有不同成员权重；它们通过推荐目标决定哪些组内语义有用。首版复用已有投影，不增设扩散模型、Transformer、重建器或多套辅助损失。

**边界与风险**：固定 H 的纯线性 HHᵀE 可以化为图平滑，不能靠改写矩阵称为结构创新。这里值得验证的是由当前表示决定的组内聚合；要用均匀成员权重作对照。该方法仍可能与 B 的行为残差重复，可能遗漏低共现物品，也不自动解决冷启动。若任务驱动聚合不优于均匀聚合，应撤回复杂部分，而不是继续堆模块。

### 实验顺序：先诊断，再验证主体，保持固定训练超参数

- **现成开关的因果检查**：在 centered 下单独关闭原 HCL，检验激活后的对比任务是否限制排序。它是损失存在性消融，不是搜索权重，也不宣称为新模型。
- **核心替换比较**：同轮 B 与新 GHE，先保持原 HCL 相同；另设新 GHE 关闭 HCL 的组，区分结构收益和辅助目标影响。若前一项诊断需要严格同轮重跑 centered，应给它独立新目录，不混用早停或源码不同的旧记录。
- **结构有效后再做机制消融**：新 GHE 的均匀成员聚合 vs 任务驱动聚合；真实群组 vs 随机重标群组。若与 B 残差重复，再检查是否能撤掉残差以简化结构。
- 全部采用999/2026/2027、相同数据指纹和协议；固定lr=.002、batch512、weight_decay=1e-5，只用 VALID 选模，TEST继续封存。检查逐种子 R@20/N@20、训练成本和诊断，不能仅凭四条超边占用改善或单种子最高值晋升。

结论状态：centered 的数值修复有证据，但本轮性能下降；上述新结构是待实现方案，尚无涨点证据。
